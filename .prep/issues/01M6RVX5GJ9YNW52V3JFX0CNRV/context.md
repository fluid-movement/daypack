Helper API and concrete fixture shape
- `type Fixture struct { Home, Library, Project, Worktree string }`; `func NewFixture(t *testing.T, withWorktree bool) Fixture`. Home and Library are temp directories separate from Project (and Worktree), not descendants of it. Set HOME, DAYPACK_HOME and XDG_CONFIG_HOME to temp locations before invoking any product code. `--library`/`--project` must also be passed explicitly in CLI helper calls; test precedence with overrides different from environment values. Because t.Setenv changes process state, tests using these helpers must not call t.Parallel.
- Fixture library: `skills/testing/SKILL.md` with YAML frontmatter `name: testing`, non-empty `description`, and a body/support file; `mcp/docs.toml` with type=stdio, a harmless command and an env reference `${DAYPACK_TEST_SECRET}`; `fragments/conventions.md` with description frontmatter; `agents/reviewer.md` with name+description frontmatter. Also allow tests to write malformed fixtures without running a future library init command. A temp project may contain a minimal `daypack.toml` with version=1, harnesses=["claude-code","pi"], skills=["testing"], mcp=["docs"], fragments=["conventions"], agents=["reviewer"]. This is fixture data, not a manifest loader implementation.
- Initialize Git using `git -C <project> init` with isolated HOME/config, repo-local user identity, signing/hooks disabled, and a minimal initial commit when a worktree is requested. Add the optional worktree on a new test branch in another temp directory; worktree `.git` is a file. Use explicit command arguments and capture errors; avoid inherited user Git config, hooks, global excludes or external signing. Cleanup via t.Cleanup; never git-config --global. Local git is the one executable fixture prerequisite, not a runtime dependency of the binary. Give a clear test failure when absent.
- `type CLIResult struct { Code int; Stdout, Stderr string }`; `func RunCLI(t *testing.T, f Fixture, args ...string) CLIResult`. Invoke real `internal/cli.Run(ctx, args, IO{...})`, not exec.Command/go run and not os.Exit. That API and `IO` are established by the CLI issue. Feed a non-TTY reader, capture stdout/stderr independently, and prepend root directory overrides. Helpers must allow explicit test-controlled stdin/TTY when needed without replacing product logic with mocks.
- `func SnapshotTree(t *testing.T, root string) map[string]TreeEntry` and `func AssertTree(t *testing.T, root string, want map[string]TreeEntry)`; entries carry relative slash-normalized path, kind (file/directory/symlink), bytes or link target. Use Lstat/Readlink; never follow symlinks into real HOME or outside a fixture. Sort diagnostics and compare exact content. Tests can select expected paths to avoid unstable Git internals; do not globally ignore dotfiles, JSON siblings or secrets.

Goldens, fake adapter, sentinel
- `func AssertGolden(t *testing.T, path string, got []byte)` compares bytes and reports a readable diff. Provide `AssertJSONGolden(t, path, got)` using encoding/json to canonicalize object keys while preserving array order and enforcing one complete JSON document. Golden update must be explicit and opt-in (e.g. -update test flag registered once); normal tests never rewrite expectations. Normalize only declared fixture root paths and platform path separators, never remove secret-like substrings or operation order. Exercise the helper with hand-built Item-shaped lists and plan-shaped text/JSON fixtures, not a fictional production renderer.
- Fake adapter is pure test support declaring a shared target `agents-skills-dir` at `.agents/skills` and a unique target `test-skills-dir` at `.test/skills`. It returns deterministic desired items including Target, Entry, Kind, Path and link target, without filesystem I/O. Use adapter issue 01M6RSR2MYB5VPVPS8WHTWTDQG's binding shapes: `Name() string`, `Supports(ArtifactType) bool`, `Desired(Entry, Project) ([]Item,error)`, plus `Notes(Project) []Note`; item variants include symlink/file/JSON entry/Markdown section/JSON array element. If that interface is implemented by then, use it directly; otherwise keep the fake's minimal descriptor and item structs local to test support, with no invented production adapter interface. Self-test declarations and deterministic output only. Target union/merge, disagreement detection, restricted-entry execution and full conformance tests belong to the adapter issue, not this foundation.
- `func PlantSentinel(t *testing.T, f Fixture) string` sets DAYPACK_TEST_SECRET to a distinctive synthetic non-credential and writes it as `DAYPACK_TEST_SECRET=<value>` into `<library>/secrets.env` with mode 0600; only references appear in definitions. `func AssertNoSecret(t *testing.T, project, sentinel string, outputs ...string)` scans every regular file under project (including hidden/untracked files) and both outputs for exact sentinel bytes. Do not log the sentinel on failure: report path/output stream. Do not follow external symlinks; independently inspect link targets and fail a link that exposes secrets.env. Library secrets.env is outside the scan root and is intentionally allowed to contain the value. Feature tests call this after apply/status/import, both success and error cases.
- Self-test secret detection using an internal pure scanner returning findings: plant a leak in a hidden file, normal file and each output stream and assert it is detected without making the outer test fail intentionally. Then verify a clean project with `${DAYPACK_TEST_SECRET}` passes. Do not test real secret resolution or execute MCP commands.

CI and verification
- On push, `.github/workflows/ci.yml` checks out source, sets up Go from go.mod (1.27.3), downloads module dependencies, and runs `go vet ./...`, `go test ./...`, and `golangci-lint run ./...`. Pin the action/linter versions in the workflow; choose a released golangci-lint version built with Go >=1.27 so it can analyze this module, and confirm its supported-version requirements when implementing. A version compatibility check is implementation validation, not a product design decision. CI may fetch tools/modules; tests themselves must remain offline and never invoke external services. If lint config is needed put it in `.golangci.yml` and use the selected linter's actual schema.
- Exact local verification: `go build ./...`, `go vet ./...`, `go test ./...`, `golangci-lint run ./...`, `prep check`. After module dependencies are cached, confirm offline execution with `GOPROXY=off GOSUMDB=off go test -count=1 ./...`; Go compilation may use its normal tool cache, while HOME used by product tests is temporary. Do not run live evals.
