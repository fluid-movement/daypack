Entry states and health
1. Start with effective manifest (entry,harness) pairs, including unresolved diagnostics. Attribute shared target operations to selected producers by their declarations and entry harness sets; unsupported stays harness-specific. Use desired ownership items plus plan diagnostics, not only Plan.Operations: a change-only plan may omit every healthy entry. Produce one entry row per selected pair, with physical operations retained in Changes. Aggregate mixed item states with a documented deterministic priority collision > drift > unresolved > unsupported > pending > ok; never hide individual operation/check detail. Include obsolete owned entries awaiting removal so removal-only plans remain visible.
2. Shared plan mapping: Create/Update/Remove/Adopt -> pending; Conflict -> collision; Drift -> drift; Unresolved/Unsupported map directly. Unchanged converged items -> ok (use Outcome/observations, not Action alone). A deleted managed item is pending repair with a missing-managed-path check; an edited managed file/wrong link is drift; an unowned conflicting item is collision; a clean library change is pending. Preserve safe-failure rules: unresolved/unsupported entries never induce cleanup or hide retained owned-path health.
3. Inspect every locked item, including no-longer-selected ones, through existing ownership observation. Add missing-managed-path checks for missing files, links or owned JSON keys/array members/Markdown sections. For managed Symlink rows validate the path, then Lstat/Readlink and Stat the link referent (no content reads); dangling/cyclic library links produce a dangling-library-link error/check and attention even when lock.Status is converged. Keep an unresolved entry unresolved while attaching its dangling-path check; do not report it healthy just because Readlink matches. Unrelated handwritten paths are outside this scan. Genuine I/O or unsafe input failures return sanitized errors (exit 1); observed broken/missing managed resources are health results (exit 3).

Check actual IsTracked for every intended-untracked managed path, independently of exclude membership; Item.Tracked=true intentionally shared tracked containers are allowed, with the same per-path tracked dominance as ExcludeBlock. Never turn a violation into success by resetting intended Tracked from observed Git state.
