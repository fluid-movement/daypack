## Implementation plan

1. `internal/library/fragments.go`: `FragmentBody(data []byte) ([]byte, error)` strips only an optional leading YAML frontmatter block (same delimiter/validation as `frontmatter.go`), keeps every other byte (CRLF, no final newline); malformed or unterminated frontmatter errors.
2. New package `internal/adapters/instructions` with pure `FragmentItem(e contract.Entry) (contract.Item, error)`: validates `Artifact.Type == library.Fragment`, `Ref == "fragment:"+Name`, valid marker; returns `{Target: contract.AgentsMD, Entry: e.Ref, Kind: contract.MarkdownSection, Path: "AGENTS.md", Marker: e.Ref, Bytes: framed body}` and `Target() contract.Target` returning `{ID: AgentsMD, Root: "AGENTS.md", Mode: FileRoot, Types: [Fragment]}`. Framing: owned LF before and after the body so marker comments sit on their own lines; body bytes untouched; reject bodies containing `<!-- daypack:`. Markers are `<!-- daypack:begin fragment:NAME -->` / end; `lock.validateMarker` forbids spaces, `--` and angle brackets, so check `fragment:NAME` passes (names are library-validated). Empty body still yields an item.
3. Extend `claudecode.Adapter` and `pi.Adapter`: add Fragment to `Supports`, append `instructions.Target()` to `Targets`, dispatch `Fragment` in `Desired` to `instructions.FragmentItem`. Existing skill/agent/MCP output must not change (existing golden files stay green).
4. Claude bridge. Add `contract.ClaudeMD = "claude-md"` and a Claude target `{ID: ClaudeMD, Root: "CLAUDE.md", Mode: FileRoot, Types: [Fragment]}`; add `claude-md: {"claude-code"}` to `readers.go`. Add optional `contract.ProjectAdapter interface { DesiredProject(entries []Entry, project Project) ([]Item, error) }`. Claude implements it: if at least one resolved entry of type Fragment is effectively selected for claude-code (entry.Harnesses nil inherits project; filter in `Registry.Desired`), return exactly one `Item{Target: ClaudeMD, Entry: <reserved bridge ref>, Kind: MarkdownSection, Path: "CLAUDE.md", Marker: "agents-md-import", Bytes: "\n@AGENTS.md\n"}`; else none. `Registry.Desired` calls it once per selected adapter after per-entry rendering, validates it with a new `validateProjectItem` (reserved ref only, declared target, valid payload) and feeds it through the same `ownership.Put` overlap check. Choose the reserved bridge ref so `apply.validateOwned` accepts it: either relax `validateOwned` for the ClaudeMD target and the reserved ref only, or pick a ref whose type prefix is `fragment` with a name library names cannot take (library names cannot contain `:` or `@`). Document the choice in a code comment; do not add it to manifest validation.
5. Core ownership of CLAUDE.md in `apply.Build` (new `internal/apply/instructions.go`, called from Build after `registry.Desired`, before `candidate`): decide the item Kind using the filesystem and the previous lock. Absent CLAUDE.md and no prior section row: convert the bridge item into an owned `File` with bytes `@AGENTS.md\n`. A prior lock File row for CLAUDE.md stays a File on later applies. Existing CLAUDE.md (or prior section row): keep the MarkdownSection. An existing unmarked `@AGENTS.md` line is handwritten and preserved; the owned section is still added. File and section ownership are mutually exclusive (lock overlap rule). Removal: clean owned stub is deleted by existing File removal; a section is removed with `RemoveSection`, leaving the handwritten file. Tracked: candidate()'s `IsTracked` path stays for the stub; for all AGENTS.md section rows and a CLAUDE.md section row force `Tracked = true` (the committed exception) in candidate or in the new instructions step, so `lock.ExcludeBlock` omits them even before `git add`. Never run git add.
6. Ordered reconciliation. Add to `internal/lock` (new `markdown_order.go`): `type Section struct{ Marker string; Body []byte }` and pure `ReconcileSections(data []byte, desired []Section, managed []string) ([]byte, error)`. Refactor `section()` to share one parser that returns every marker span (no second regex). Semantics: validate whole document and bodies; desired markers must be within `managed`, no duplicates; replace managed sections in existing slots in desired (manifest) order, drop unused managed slots, insert extras after the last managed slot, else after the last existing daypack section, else at EOF; every unmanaged byte span is copied unchanged in original order (no trim/normalization, CRLF and missing final newline preserved). Invalid markers (duplicate, nested, unclosed, unmatched, injected in body) return an error and no output. Keep `SetSection`/`RemoveSection` public behavior.
7. Wire into `executeBatch` in `internal/apply/execute.go`: for a batch whose first item is MDSection at `AGENTS.md`, collect all section operations of the batch and call `ReconcileSections` once, with desired = every non-removed section row in the batch plus retained owned rows in manifest order, managed = markers of the batch's create/update/remove/unchanged-but-owned rows. Manifest order must come from `Build` (keep an ordinal on `work`, e.g. `order int`, set from entry index; do not use lock or plan sort order). Detect a reorder-only change in the plan: when all body hashes converge but the computed file bytes differ from disk, emit `plan.Update` for the affected section rows (reason "reorder") so the report shows it and a second apply is a no-op; avoid rewriting identical bytes (`fs.write` already skips them). If a section in the path is Drifted/Conflict/Unresolved and not forced, skip the whole path batch with nonzero skipped outcome rather than partially reordering; other targets proceed. `Execute` stamp checks and `approve` must still hold. A missing AGENTS.md is created only when at least one section is desired; removing the last section leaves the file.
8. Dry-run (`Prepare`/`Plan` without `Execute`) reports section create/update/reorder/remove and the CLAUDE.md import/stub; writes no target, lock or exclude changes.
