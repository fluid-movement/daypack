API contract (concrete Go rendering of the requirement)
- `type ArtifactType string` with constants Skill="skill", MCP="mcp", Fragment="fragment", Agent="agent"; these singular values are the reference prefixes, not plural directory names.
- `type Artifact struct { Type ArtifactType; Name, Path, Description string; MCP *MCPDefinition }`. Path is absolute: skill folder for Skill; source file for other types. MCP is nil for non-MCP. Definition values and references remain unexpanded.
- `type Severity string` with Error="error" and Warning="warning"; `type Problem struct { Severity Severity; File, Field, Message, Hint string }`. File is the source path; fields are stable names such as `frontmatter.name`, `frontmatter.description`, `env.API_KEY`, `headers.Authorization`, `args[0]`, `url`, `name`. Messages identify the issue without including sensitive values.
- `type Library struct` holds root, discovered artifacts and collected parse/validation problems; callers must not need to know its map layout. Expose `func Load(libraryPath string) (*Library, error)`, `func (l *Library) Resolve(ref string) (Artifact, error)`, `func (l *Library) List(kind ArtifactType) []Artifact`, `func (l *Library) Validate() []Problem`.
- `func DefaultPath() (string, error)` resolves nonempty DAYPACK_HOME first, then nonempty XDG_CONFIG_HOME joined with daypack, then os.UserHomeDir() joined with `.config/daypack`. Explicit nonempty path passed to Load wins over all environment settings; empty Load path uses DefaultPath. Convert to cleaned absolute paths relative to invocation cwd; do not expand a literal '~' in environment/path strings. Treat empty environment values as unset. No home lookup if an explicit or environment override resolves the path.
- Missing library/root-not-directory yields an error naming the path with a hint `daypack library init`; Load never creates it. Root read/I/O errors return errors with file paths. Parse/schema problems in individual artifacts are retained in Validate so doctor can report multiple problems, rather than silently dropping invalid files or stopping at the first one. Resolve of an invalid artifact must return a validation error, not a seemingly usable partial definition. List must not trigger secret resolution or command execution.
- `type NotFoundError struct { Type ArtifactType; Name, Closest string }` with Error() string, discoverable by errors.As. Resolve parses exactly one `type:name`; unknown type, missing name, extra colon or invalid name is invalid input, not a not-found result. For an absent valid name choose closest name within that type using edit distance, lexical tie break, and empty Closest if that type has no entries. Do not suggest a different artifact type. List and Validate output are deterministic (type/name, then file/field/severity); List of an empty valid type is an empty slice.

Names and native metadata
- Match names against `^[a-z0-9-]{1,64}$` exactly; do not introduce a stricter first/last-character rule. Names are case-sensitive and unique PER TYPE: skill:docs and mcp:docs may coexist. Keep discovery findings before building a keyed index, so duplicate logical entries cannot silently overwrite each other. Current filenames generally make exact duplicates impossible, but validate duplicates in the collected/index-building path and test that path directly.
- Skill: SKILL.md must exist and have YAML frontmatter with name equal to directory basename and a nonempty description. Missing/malformed frontmatter, mismatched name and blank description are validation errors, with source file and field. Supporting files/subdirectories are opaque native content and not unknown-file warnings.
- Agent: native Claude Code subagent Markdown, with frontmatter name and description; name must equal file stem. Parse only necessary metadata, do not rewrite the Markdown or reject unrelated native keys. Fragment: plain Markdown allowed; frontmatter/description is optional. Descriptions returned by Resolve/List come from these fields or MCP description; no generated prose.
- Unknown files are ignored as artifacts, retained as Warning problems for a later doctor renderer, never treated as errors. For example README or an unrecognized extension at root/artifact collection level. Known housekeeping `.git`, `.gitignore`, and `secrets.env` are not artifacts and are not traversed/parsed. Do not warn about every support file under skills. Recognized files with invalid names remain validation errors, not unknown-file warnings. Library missing artifact-type directories are empty collections, not errors.

Shared MCP schema and parsing
- `type MCPDefinition struct { Description string; Type string; Command string; Args []string; URL string; Env map[string]string; Headers map[string]string }`, with TOML fields `description`, `type`, `command`, `args`, `url`, `env`, `headers`. Expose `func ParseMCP(data []byte, source string) (MCPDefinition, []Problem)` and `func ValidateMCP(def MCPDefinition, source string) []Problem` so the later manifest loader validates inline MCP by exactly the same code. Retain TOML field-presence information internally so forbidden fields are rejected even if explicitly empty. No separate required-secrets field.
- type is exactly stdio or http. stdio requires a nonempty command, accepts args/env, and rejects url/headers. http requires a nonempty url, accepts headers, and rejects command/args/env. Description optional. TOML syntax/type errors identify file/field and never echo an unsafe line of input. The requirement's example demonstrates both alternatives; do not create a fixture containing both stdio command and HTTP url.
- Inline manifest `[inline.mcp.<name>]` later adds an optional harnesses field; that field is manifest metadata stripped before the common MCP parser/validator. This issue must not add harness selection or inline manifest loading to Library.
- References `${VAR}` and `${VAR:-default}` are allowed in env, headers, url, command and args. Use shell-style variable identifiers `[A-Za-z_][A-Za-z0-9_]*`; do not expand references, execute commands or read secrets.env. `func (d MCPDefinition) RequiredVariables() []string` returns sorted deduplicated variable names appearing without `:-default` across all those fields. Multiple references in one string count; a variable used once with a default and elsewhere without one is required. A reference with a default is not independently required, including an empty default.
- For env/header keys matching the exact case-insensitive, unanchored pattern `(key|token|secret|password|passwd|auth|credential)`, reject plain literal values and hint to use `${VAR}`. A reference can be embedded in a value, e.g. `Authorization = "Bearer ${EXAMPLE_TOKEN}"`; this explicit example must pass. `${VAR:-default}` is allowed by this requirement; do not supersede that with a different secret-source policy. Non-secret keys may contain plain literals, e.g. API_BASE="https://x.test". Empty literal under a secret-looking key is still a literal. Reject malformed reference syntax with a field problem; do not print its contents.
- args/url secret suspicion is a WARNING, not a validation failure, even where the value looks sensitive. Recognize documented prefix cases `ghp_`, `sk-`, `xox`, sensitive query parameter names key/token/secret/password, and long high-entropy strings. Keep the heuristic deterministic and unit tested; an implementation-level baseline is a >=32-character token with Shannon entropy >=4.5 bits/character, excluding `${...}` reference spans. State thresholds in code comments; they are a heuristic, not proof. Parse URLs without expanding references and inspect query keys case-insensitively. References themselves must not trigger warnings. Report file/field and advice to move the value into an environment variable; NEVER include the suspected value in diagnostics, errors, or test diffs.
- Harness expansion capability is deliberately OUT OF SCOPE: a reference in command/url/args is valid library data even if Pi cannot expand it. Adapter issues later emit unsupported reports. Library definitions are trusted user data; validation must not add an approval prompt, execute an MCP server, query a secret source, or produce generated harness files.
