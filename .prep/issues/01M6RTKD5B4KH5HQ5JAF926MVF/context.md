## Scope and dependency

Implement repository Git `post-checkout` installation/removal and an unattended policy for the ordinary apply pipeline. This does not manage harness hook artifacts/settings, install a global hook, recurse into nested projects, or bootstrap fresh clones. The [hooks out of v1 decision](/decisions/01M6RVSCSZ1P142TVB1E5AZW3V.md) concerns harness hooks, not this explicitly requested Git integration. A clone needs manual `daypack apply` and `daypack hook install` because Git does not clone hooks.

Dependency `01M6RSR2FKVBKQHS28Z7J39NHB` is currently defined, not ready/claimed/done: `internal/apply/doc.go` is only a package stub. There is no apply engine API or registered apply command on this main. Do not implement a second reconciliation engine in this issue. Integrate with the dependency once its implementation/API lands; the proposed signatures below are local extension points, not claims of existing APIs. CLI contract dependency `01M6RVX5E50998CXQHV942P828` is done. Recheck dependency state before ready/implementation; pending apply implementation is the readiness blocker.

## Hook package and CLI integration

Add `internal/hooks/hooks.go` (package hooks), `internal/hooks/hooks_test.go`, `internal/cli/hook.go`, and external CLI integration tests `internal/cli/hook_test.go` (package cli_test to avoid the testutil -> cli import cycle). Suggested new API: `Install(ctx context.Context, projectDir, executable string) (Result,error)`, `Uninstall(ctx context.Context, projectDir string) (Result,error)`, `Result struct { Path, Invocation string; Changed, Conflict bool }`. The result is hook-specific metadata only; do not duplicate plan/lock/adapter types. A private `hookPath(ctx context.Context, projectDir string) (string,error)` uses `exec.CommandContext` with argv `git -C <projectDir> rev-parse --git-path hooks`, resolving a relative result against projectDir, then appending post-checkout. Follow Git's core.hooksPath resolution; do not modify core.hooksPath or hardcode `.git/hooks`. Reject non-repository/bare destinations with a normal CLI error. Install does not require a manifest/library; it must work before daypack.toml exists.

`hookCommand() *cobra.Command` has `install` and `uninstall` leaves, both cobra.NoArgs and SetHandler handlers. Install obtains os.Executable(), makes its path absolute (resolve symlinks if needed), and passes it to hooks.Install. No binary-path public flag is necessary: inject an executable via the hooks API in package tests. Hook install/uninstall errors use normal CLI codes; a foreign hook is Attention with a safe quoted Invocation in both text diagnostics and JSON result so users can edit their hook manually. Missing uninstall is a successful no-op; repeat installation of the exact same owned script is idempotent. A different existing hook, including symlink/dangling symlink/directory or edited daypack hook, is never overwritten or removed. Use Lstat and exclusive creation (O_CREATE|O_EXCL), executable mode (0755), and clean up a partially written newly created file on write/close/chmod failure. Do not append to foreign hooks or execute their content. Hook ownership is separate from the project apply lockfile because the hooks directory is shared between worktrees.

Render a versioned, recognizable POSIX sh script containing an absolute shell-quoted executable and `apply --auto` with stdin from /dev/null and explicit successful termination even if execution fails or the binary has moved. Quote apostrophes as well as spaces/$/backticks; reject NUL/CR/LF paths rather than emit malformed scripts. The manual Invocation must also preserve the caller hook's exit status (for example a subshell with `... apply --auto </dev/null || :`). Do not use exec (which would bypass the fallback), embed the installing checkout's root/library, assume daypack is in PATH, or pass Git's three checkout arguments through to apply. Git invokes post-checkout in the target worktree; normal discovery from that cwd handles branch checkout and worktree add. Keep stdin disconnected even for a GUI client or a manual chain. Removal verifies the full canonical versioned script, including its safely encoded stored executable path, not merely a marker line; recognize the stored path even if the currently running binary moved. Foreign or modified content remains byte-for-byte unchanged. Document the ordinary manual-chain hint and that no other Git hooks/config are changed.

## Auto policy extension

Add `--auto` to the dependency's `internal/cli/apply.go`; add auto policy in the dependency's `internal/apply` options/planning stage (suggested `Options.Auto bool`, reusing the actual options type once it exists). Keep the engine unaware of Cobra/streams/CLI exit constants. It returns its existing plan/results; the CLI applies the auto exit policy. A useful new pure helper is `autoEntries(entries []contract.Entry) (allowed []contract.Entry, skipped []string)` in `internal/apply/auto.go`: filter every Inline MCP entry by provenance before adapter rendering, irrespective of previous lock state, Gated flag, --yes or interactive terminal. Preserve the skipped ref set through reconciliation. Existing lock rows for a still-selected skipped inline ref must remain owned/present and must not become stale removals merely because auto filtered its desired output. Remove no MCP config/approval/helper for those refs, and write/create/adopt none; normal genuinely removed entries retain ordinary safe reconciliation. Reuse the dependency's preservation mechanism for unresolved entries if available; do not duplicate reconciliation or trust history. Record one deterministic skipped entry outcome/notice per inline ref using existing plan operations/notes; use a valid existing diagnostic action when no writable target exists rather than invent a second plan schema. Always include a single actionable line `Inline MCP servers skipped during auto-apply; run 'daypack apply'.` Do not dump inline command/URL/env/header values into that notice.

Auto is non-interactive even with a terminal and never grants force/adopt/inline consent. Reject explicit combinations with --force or --adopt as Usage before work; --yes cannot bypass auto exclusion. Retain ordinary --dry-run write suppression. Library-backed entries still apply without inline confirmation. Runtime validation, collision/drift, unresolved-reference, missing-library and I/O failures become safe visible diagnostics with exit 0 for a valid apply --auto invocation; normal manual apply retains codes 1/3. Parse/usage errors retain Usage; the installed shell wrapper still exits 0 for any failure. Do not globally mask cli.Run errors or change other commands. No-manifest auto text invocation is silent, exits 0 and writes nothing, including no lock/exclude/library access. For JSON preserve the CLI's single success envelope even for a no-op; no mixed text on stdout. Introduce an exported sentinel `manifest.ErrNoManifest` in discover.go, wrap it at the existing absence return and detect via errors.Is; preserve the current human hint and do not classify permission/malformed/nonregular-manifest errors as absence. This small discovery extension belongs here if the dependency has not already introduced typed absence. Do not match error strings or use a duplicate search algorithm.

Follow [trust](/decisions/01M6V8JQ337RMMYWKV4S3DF8ZW.md), [ownership](/decisions/01M6RVX4S7600YVGAAE9282MYS.md), [git exclusion](/decisions/01M6RTMHKZSZKJ69XSNSDEBKFW.md), [AGENTS.md committed-section exception](/decisions/01M6TEGPWWH1VTFJE4S8GG5JJ9.md), and [secret references](/decisions/01M6RTMHP019HC90RGT8BF25PR.md). Already-converged committed sections use lock's existing adoption semantics, not --adopt.
