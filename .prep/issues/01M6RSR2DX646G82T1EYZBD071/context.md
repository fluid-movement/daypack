New concrete API/layout
- In `types.go`: `type Kind string` with symlink/file/json-entry/json-array-element/md-section; `type Item struct { Target, Entry string; Kind Kind; Path, Link, Hash, File, Key, Value, Marker string; Tracked bool; Preserve bool }` with TOML tags matching the requirement. Preserve records a pre-existing user-owned array membership so cleanup never deletes it; it must survive Save/Load. Path is the canonical project-relative container path for ALL kinds; File, when present for compatibility with the requirement's example, must equal Path (reject ambiguity). Link is a symlink destination, which can be an absolute library path; it is not a project write path. Value is the string member for array-element ownership, Marker names the Markdown section.
- `type Lock struct` with version and private item storage; `func New() *Lock`; `func Load(projectRoot string) (*Lock,error)`; `func (l *Lock) Save(projectRoot string) error`; `func (l *Lock) Items() []Item`; `func (l *Lock) Find(identity Item) (Item,bool)`; `func (l *Lock) Put(item Item) error`; `func (l *Lock) Forget(identity Item)`. Items returns copies in stable order. Missing lock means a new empty v1 lock; malformed/unsupported lock must error, never be treated as empty ownership.
- Identity is filesystem path for whole-file/symlink; path+kind+key for JSON values; path+kind+key+Value for array members; path+kind+Marker for sections. Target/Entry describe producers, not identity. Detect duplicate/incompatible identities and whole-file ownership overlapping sub-entry ownership. Two unrelated JSON keys/Markdown sections in one file are independent.
- `type State string` values ok/missing/drifted/collision; `type Observation struct { State State; Converged, Adopt, Preserve bool }`; `func (l *Lock) Status(projectRoot string, desired Item) (Observation,error)`. Desired's hash/link/value supplies comparison with current content; the lock row supplies previous content. Unreadable/malformed containers are errors, not missing. A desired match converges silently (and can be adopted); an owned previous match may be changed; owned content differing from previous AND desired is drifted; an unowned unequal location is collision. Keep machine-readable distinctions, do not infer from diagnostic strings.
- `func HashJSON(value []byte) (string,error)` uses SHA-256 of canonical JSON (sorted object keys, compact separators, preserve array order and JSON number precision via Decoder.UseNumber; reject invalid or multiple documents). File hash is SHA-256 of exact bytes; Markdown hash is exact body bytes inside markers; links compare Readlink targets. Use lowercase hex SHA-256 consistently.
- Pure edit helpers in json.go/markdown.go accept bytes plus Item and desired bytes where needed and return new bytes/error: e.g. `SetJSON(data []byte,item Item,value []byte) ([]byte,error)`, `RemoveJSON(data []byte,item Item) ([]byte,error)`, `SetSection(data []byte,marker string,body []byte) ([]byte,error)`, `RemoveSection(data []byte,marker string) ([]byte,error)`. Apply ownership/Status checks before helpers mutate disk; provide owned-item removal helper or tests composing these primitives. Do not delete unowned containers or unrelated siblings when their last managed entry disappears.

Ownership behaviors and safety
- Handle whole file, symlink, JSON key, JSON string-array element and Markdown section. For unowned exact-match objects, adopt with no flag. For an already-present array member, record Preserve=true: cleanup forgets its row but retains that user-added member. Newly inserted members may later be removed, without deleting other values or reordering them. Reject wrong array types and ambiguous duplicate membership rather than deleting arbitrary occurrences.
- An owned tracked item equal to desired converges even if the historical hash differs; equal to previous hash is safely updateable; anything else is drift. --force and --adopt are decisions exposed to later planner/apply; this package reports them and does not prompt or force by itself. No registry or cross-project modifications.
- JSON paths need escaped segments for keys containing gjson/sjson punctuation (especially MCP names containing dots); do not concatenate untrusted names into executable path syntax. Validate full JSON before edits, including duplicate owned keys/ambiguous paths. Preserve unknown keys, ordering, indentation and trailing newline. Use gjson/sjson raw edits/format options and byte-diff tests; do not assume their default insertion formatting meets acceptance. Refuse unsupported/malformed documents without modification.
- Markdown markers are exactly `<!-- daypack:begin NAME -->` / `<!-- daypack:end NAME -->`. Duplicate, nested, unmatched or inverted markers are errors; never consume text outside the unique pair. Reject marker names containing newlines/marker syntax. Exact content outside the pair remains byte-identical.
- `func ValidatePath(projectRoot, relative string, targetRoots []string) error` enforces nonempty relative paths, no absolute/volume paths and no `..` segments (reject before Clean), containment within a declared target root with path-component boundaries. `.daypack` is a special core-owned root. Validate serialized records as well as new descriptors; the caller must supply trusted adapter roots rather than trusting roots supplied by lock data.
- Use Lstat for `.daypack`, lock.toml and every existing parent; reject symlinked `.daypack` and, conservatively, symlink parents for writes/removals. Never follow the final symlink when observing/removing a symlink Item; its target may legitimately be outside project. Reject tracked `.daypack/lock.toml` before saving/applying. Recheck path safety immediately before each mutation, not just at load.
- Same-directory temp file + close + rename for every write, restrictive permissions for lock, cleanup temp on error. Do not rewrite identical bytes. Lock persistence happens after each successfully applied batch; do not record failed operations. Expose injectable write/rename failure points in tests. This issue guarantees atomic individual writes and batch Save behavior, not a multi-file transactional apply/crash-recovery engine. Do not promise recovery from an arbitrary kill between target rename and lock rename without a journal; legacy end-to-end requirement examples belong to apply, final package-level acceptance is the current baseline.

Git exclusion
- `func ExcludeBlock(projectRoot string, items []Item) (string,error)` returns sorted/de-duplicated managed untracked container paths plus `.daypack/`, between exact `# daypack begin <absolute project root>` and end markers. Do not emit entry keys as paths, exclude a whole shared config with any tracked=true exception, or exclude handwritten siblings by excluding a parent directory. Escape gitignore metacharacters; reject newline-bearing roots/paths used in marker blocks.
- Add `func UpdateExclude(projectRoot string, items []Item) error` and read-only block inspection for stale roots. Resolve location using `git -C <root> rev-parse --git-path info/exclude` and tracking using `git ... ls-files` with argument arrays, not shell interpolation. Resolve relative Git output against the requested root. Worktree `.git` is a file; never concatenate `.git/info/exclude` by assumption. Preserve other roots' blocks and all unrelated bytes; regenerate only this root's block; `.daypack/` remains while this project uses a lock. Provide explicit block-removal support for eject, so an empty/retired ownership block can be removed without deleting others. Outside Git, skip exclusion silently; Git execution/permission failures inside a repository are errors. Stale-root detection is read-only, for status to report later.
- Tracked is computed by core planning using Git, never adapters. AGENTS.md's managed section is intentionally tracked; pre-existing tracked .mcp.json stays visible. `.claude/settings.local.json` is generated/untracked. No blanket .claude/ exclusion.
