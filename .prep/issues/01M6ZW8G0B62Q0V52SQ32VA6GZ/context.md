### Verified current Codex project conventions

- [Local skills](https://learn.chatgpt.com/docs/build-skills): repository discovery scans `.agents/skills` from CWD through repository root and follows symlinked skill directories. User skills use `~/.agents/skills`; admin skills `/etc/codex/skills`; system skills are bundled. This adapter should generate only the project shared target, not `.codex/skills`.
- [MCP](https://learn.chatgpt.com/docs/extend/mcp?surface=cli): project file `.codex/config.toml`, one `[mcp_servers.<name>]` table per server. STDIO uses `command`, optional `args`, static `env` map, forwarded `env_vars` array and optional `cwd`. `env_vars` string entries name local inherited variables; source-tagged objects also exist for remote executors. HTTP uses `url`, `bearer_token_env_var` (name, not token), static `http_headers`, and `env_http_headers` mapping header names to environment variable names. No general `${VAR}` substitution guarantee was found. Only the subset representable by daypack's existing schema is in scope; omit Codex type/description fields. OAuth/helper/remote options are not part of the library schema.
- [Configuration precedence and trust](https://learn.chatgpt.com/docs/config-file/config-basic) and [reference](https://learn.chatgpt.com/docs/config-file/config-reference): config layers include CLI overrides, user `$CODEX_HOME/config.toml` (default `~/.codex/config.toml`) and project `.codex/config.toml`; closer project layers override less specific ones. Project config loads only when trusted. User-level `projects.<path>.trust_level` accepts trusted/untrusted; untrusted projects skip project `.codex/` layers. Generate a static advisory note; do not write a trust decision, edit global config, or assert the project is trusted. The config-trust rule does not establish identical gating for `.agents/skills` or AGENTS.md, so do not make that extra claim.
- [AGENTS.md discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md): Codex reads global guidance, then root-to-CWD guidance. At each directory it prefers `AGENTS.override.md`, otherwise `AGENTS.md`, then configured fallback names; at most one file per directory. Deeper guidance follows earlier guidance; the combined default cap is 32 KiB. Reuse the existing root AGENTS.md managed sections. Document that an override can mask the generated root file and the byte cap can truncate instructions; do not edit overrides or force global limits.
- [Custom agents](https://learn.chatgpt.com/docs/agent-configuration/subagents): project-level custom agents DO exist as standalone `.codex/agents/*.toml` files (user scope `~/.codex/agents`). Required fields: `name`, `description`, `developer_instructions`; optional model settings include `model` and `model_reasoning_effort`. Agent name is determined by the field. Permissions/provider/MCP are inherited from the parent and cannot be overridden in that file. Current docs describe `agents.enabled` as true by default; no experimental flag or per-agent role registration is required for this layout. This answers the requirement's conditional subagent question affirmatively, without promising compatibility with older installed Codex versions.

### MCP transport and ownership

`library/mcp.go` defines `MCPDefinition{Description,Type,Command,Args,URL,Env,Headers}` and `ValidateMCP`; it rejects unknown schema fields and literal values under secret-looking env/header keys. Use `internal/secrets/reference.go` to classify reference spans; retain existing validation and return only field names for unsupported capabilities (pattern in `pi/mcp.go`). Sort output deterministically. Compare Authorization header names case-insensitively and reject ambiguous duplicates instead of emitting conflicting credentials. Do not write `${VAR}` literals and assume runtime interpolation.

The main engineering gap is core TOML ownership: current kinds in `internal/lock/types.go` are symlink, file, json-entry, json-array-element, md-section. `contract/types.go` aliases these; `adapters/merge.go` validates kind-specific payloads; `internal/plan/types.go` validates serialized operations. Add an explicit TOML-table kind and implement semantic hashing, key identity/overlap validation, observation/status, table set/remove and execution dispatch. Review `lock/json.go`, `lock/status.go`, `lock/exclude.go`, `apply/reconcile.go`, `apply/execute.go` and related owned-item validation/removal paths. Existing BurntSushi/toml dependency parses TOML, but does not by itself provide byte-preserving source edits; account for that work explicitly.

Own only one server subtree, not the whole config or `[mcp_servers]` parent. Preserve unrelated user tables, values, comments and layout byte-for-byte; this includes root Codex settings and other servers. Detect invalid TOML and unsafe/unsupported table layouts before writes. Handle quoted keys safely. Retain existing collision refusal, explicit --adopt, edited-owned-table drift protection, --force, stale cleanup/eject, symlink containment, atomic commits, and snapshot rechecks. Semantic hashes should tolerate formatting-only changes to an owned table. Preserve pre-existing config containers on last removal. Git exclude behavior is per existing tracking policy, never exclude the entire .codex directory. Dry run must mutate neither files, lock nor excludes.
