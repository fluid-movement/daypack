## Existing implementation to reuse

- `internal/library/types.go`: `ArtifactType` (`Skill`, `Agent`, `MCP`), `Artifact`, `MCPDefinition` (in `mcp.go`), `Problem`. `Load(root)`, `Library.List(kind)`, `Resolve(ref)`, `ValidateName(kind,name)` already exist. Names are 1-64 lowercase letters/digits/hyphens; do not silently slugify, rename, or overwrite native content. Report incompatible names/frontmatter as skipped. Claude subagent identity comes from frontmatter `name`, not filename; its source filename need not match. Skill name comes from frontmatter when present, otherwise directory basename, but native library validation still requires matching name and description; do not invent missing metadata.
- `internal/library/write.go`: `Add(root, AddOptions{Type,Name,Source})` validates native content and stages/exclusively publishes. `safePath`, `nativePath`, `copyNative`, `validateArtifact`, `stagePath`, `publish` are private and reusable inside library. `copyNative` rejects symlinks, including ancestors; never weaken that invariant globally to implement import. Resolve an allowed top-level skill symlink first; import a materialized tree with regular files. Support symlinked SKILL.md by materializing its regular-file target; reject broken links, cycles, directory escapes inside the tree, and special files with a safe diagnostic. Directory roots/targets must not point into excluded plugin or synced trees. Preserve all support files and executable permission bits, markdown/frontmatter bytes, and unknown native frontmatter fields.
- `internal/library/mcp.go`: `ParseMCP([]byte,source)`, `ValidateMCP(d,source)`, `d.RequiredVariables()` already validate stdio/http, secret-looking env/header keys, variable grammar, and suspicious args/url (warnings). `secretKey` and `suspicious` are private. Expose small wrappers `IsSecretKey(key string) bool` and `LooksLikeSecret(value string) bool` here and use the same implementations in validation and import; do not duplicate regex/entropy/query heuristics.
- `internal/secrets/reference.go`: reuse `ParseReferences`, `ValidName`, `EnvReference`. `Source`/`EnvSource` produce runtime argv, not importer storage or resolution. Never evaluate references, look up environment values, execute helpers, or source an env file during import.
- `internal/library/secrets.go`: `WriteSecrets(root, projectRoot string, values map[string]string) error` is the storage contract already implemented and tested by `secrets_handoff_test.go`. It writes only `<selected library>/secrets.env`, owner-only 0600, outside the current project/worktree; checks Git hygiene, symlinks, supported syntax and conflicts, preserves existing bytes and writes the whole server batch atomically. Do not create another dotenv parser/writer or use a separate hard-coded global config path. `--library`/DAYPACK_HOME/XDG/HOME selection determines the store.
- `internal/plan/types.go`, `render.go`: reuse `Plan`, `Operation`, actions/outcomes, `contract.Note`, `Normalize`, text/JSON reporting. `internal/cli/plan.go` has `PlanResult`; `output.go` has `Result`, exit constants Success=0/Error=1/Usage=2/Attention=3. A plan contains only safe presentation data; no raw MCP definitions or secret batches. `plan.PreviewMCP` exposes args/url, so never call it on an unscreened candidate (omitting MCP preview is sufficient).
- `internal/adapters/contract` and `adapters/registry.go`: adapters currently render desired PROJECT output; `DefaultRegistry()` currently registers only Claude skills/agents, no Pi or MCP scanner. `claudecode/skills.go` and `agents.go` are renderers, not import readers. Do not add scanning to `contract.Adapter`, call `Registry.Desired` in reverse, or register Pi solely for this command.
- `internal/manifest` entries already reuse `library.ArtifactType`/`MCPDefinition`. `internal/lock` has `HashBytes`/`HashJSON` plus project-relative mutation/ownership helpers. Reuse hash primitives if useful, but import creates no manifest, lock, ownership rows, git excludes, approvals, or project output; `lock.WriteFile` is for project-relative managed writes and must not be repurposed for global library paths.

Candidate holds a `library.Artifact`, source provenance, private native bytes/tree and private secret batch; do not marshal candidates or include them with `%v` in errors. Keep secret-bearing fields unexported and avoid error wrapping that dumps JSON/TOML/YAML values. Return sanitized field-level reasons only. Import rescans on each invocation (no persisted plan file).

Extend library minimally rather than duplicate its internals:

- `func CheckSecrets(root, projectRoot string, values map[string]string) error`: read-only preflight sharing private validation/loading/conflict logic with `WriteSecrets`. No MkdirTemp/Chmod/write in this path. Check in-memory batches against each other too. WriteSecrets rechecks on commit.
- `func ValidateNative(source string, kind ArtifactType, name string) (Artifact, error)`: exported read-only wrapper around existing safe native validation for materialized regular sources; importer validates source tree structure separately without creating a temporary directory during dry-run. A source skill symlink is resolved before this call; for a symlinked SKILL.md use an equivalent read-bytes metadata helper in library instead of staging during preview. Reuse `metadata`, do not add another native schema validator.
- `func AddMCP(root, name string, definition MCPDefinition) (Artifact, error)` in `internal/library/write.go` or `import.go`: TOML-encode with existing BurntSushi/toml, validate via existing ParseMCP/ValidateMCP, and reuse nativePath/stagePath/publish with exclusive destination creation. ## Secrets, equality, and commit order

For each secret-looking env/header key, retain valid pure references; literal values (including Bearer-prefixed strings) become a reference to a stored COMPLETE original value. Allocate `<SERVER>_<KEY>` uppercased, replace hyphens with underscores; replace other non-identifier key punctuation with underscores and prefix `_` if needed for a leading digit, then validate with secrets.ValidName. No suffix guessing on conflict. Do not allocate the reserved names listed in acceptance. Detect allocation collisions across keys, env/headers, servers and existing secrets.env; equal values can share a variable, differing values skip the entire affected server. A mixed reference/literal credential or secret-bearing default must not pass as a harmless reference: report/skip when safe conversion cannot preserve it without copying plaintext. For args/url, library.LooksLikeSecret means skip the server; library warnings about these fields are blockers for importer even though normal library validation merely warns. Report only source, field, reason, variable NAMES, never values.

Preflight all candidates without writing: validate native content/trees and sanitized MCP definitions, compute content identity, compare library entries and secret batches, build deterministic sorted plan and provenance. Identity is native bytes for agents; full relative file paths + bytes + executable bits for skills (not just SKILL.md); canonical semantic MCPDefinition including env/header values after normalization and proposed secret values BEFORE discarding them. JSON key order/TOML formatting and missing-vs-empty optional containers must not create false differences. Reuse existing MCP type, not a second server schema. Real-path dedupe prevents copying the same skill twice while retaining aliases in Sources.

Group same type/name first: differing candidate contents are conflicts for the group, skip all rather than choose first. Existing occupied/invalid/different library destinations are never overwritten. Identical candidates dedupe by content, including across harnesses; choose an existing identical artifact first, otherwise a stable lexicographic valid name/source. Record all contributing source aliases and the chosen destination. Compare existing sanitized MCP using its referenced secrets from the same checked store where necessary; absence/unverifiable equality is not permission to overwrite. A repeated import is Unchanged, not a new import; cleanup provenance may still be shown.

Dry-run returns planned operations and safe diagnostics, writes NOTHING (including temporary files, secrets.env, dirs, git config/index/excludes or native sources). For actual import, process nonconflicting groups in stable order: recheck destination/source identity, WriteSecrets for the COMPLETE per-server batch, then AddMCP; never publish definition after failed secret storage. Add native artifacts through Add from resolved/materialized private staging; clean staging on errors. A destination race is a reported conflict/failure, never an overwrite. Partial independent success is supported, not a global rollback: a later publication failure can leave an unused stored variable, which is safe/idempotent; report failure and no cleanup eligibility. Never delete/rewrite source configs, even on successful import or error.

Use plan.Create + Planned/Applied for new copies; Create + Unchanged for verified existing equivalent entries; Conflict/Unsupported/Unresolved + Skipped with safe reasons. Supply absolute destination Path, stable Target such as library-skills/library-agents/library-mcp, Kind lock.File (presentation only, never persisted ownership), Entry `type:name`, harness provenance in Sources/notes. Plan.Normalize requires Target/Path for non-diagnostic rows. No gates/prompts: import stores definitions and never starts MCP programs. SafeToRemove is false in dry-run and for conflicts, failure, unsupported, excluded or lossy items; true only after a successful copy or verified equivalent existing library artifact. Preserve exact original JSON pointers (escape ~ and /) for per-project keys and unusual server names. Cleanup output lists original paths/entries for manual removal; it must not claim source parent trees or whole state files are removable.
