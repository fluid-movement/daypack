Concrete package API and layout
Add internal/plan/types.go, gate.go, render.go and their tests/testdata; update doc.go to describe the pure boundary. Use the following API contract (small private helper names are free):
- type Action string: Create, Update, Remove, Adopt, Conflict, Drift, Unresolved, Unsupported. Marker mapping: create "+", update/adopt "~", remove "-", conflict "!", drift "?", unresolved/unsupported "x". Adopt is needed by the downstream apply algorithm and means ownership-only change; it does not overwrite content. No-op/converged items normally need no operation.
- type Outcome string: Planned, Applied, Skipped, Failed, Unchanged. A hand-built operation with omitted Outcome normalizes to Planned. Applied describes successful execution supplied by caller; never claim execution from rendering. Preserve the action/marker and gated flag in final reports, adding outcome and reason rather than replacing them.
- type MCPPreview struct { Type, Command string; Args []string; URL string; RequiredVariables []string } with explicit lower-case JSON tags. No Env, Headers, content bytes, resolved credentials, or arbitrary error object.
- type Operation struct { Target, Harness, Entry string; Kind lock.Kind; Path, Link, Key, Marker string; Action Action; Outcome Outcome; Gated bool; Reason string; MCP *MCPPreview }. Here Marker is the Markdown ownership marker, NOT the action glyph. JSON includes a distinct derived "marker" glyph; serialize ownership Marker as "section" to avoid ambiguity. Include explicit lower-case JSON tags; gated=false must be represented. Target is the physical target ID. Harness is optional context for unsupported/unresolved entries with no physical target. Entry is always type:name. JSONArrayElement needs a safe string member discriminator (add Member string); use it for identity/order/display, never raw contract.Item.Value.
- type Summary struct { Create, Update, Remove, Conflict, Drift, Unresolved int } with lower-case JSON tags. These count glyphs: Adopt increments Update; both unresolved/unsupported increment Unresolved. Emit all six counts including zero; sum equals number of report operations. Outcomes have a separate deterministic count summary (map[string]int is sufficient).
- type Plan struct { Operations []Operation; Notes []contract.Note }. JSON representation also includes the derived marker summary and outcome counts. Use empty arrays rather than null in an empty plan. Notes contain already-safe display messages supplied by caller.
- func PreviewMCP(d library.MCPDefinition) MCPPreview: copy only raw Type/Command/Args/URL and d.RequiredVariables(); copy Args and variable slices. Never resolve, invoke a command, or retain env/header maps.
- type ReportOperation struct { Operation; Glyph string } with Glyph tagged json:"marker"; the embedded Operation tags put the Markdown marker under "section". type Report struct { Operations []ReportOperation; Summary Summary; Outcomes map[string]int; Notes []contract.Note } with explicit JSON tags. func (p Plan) Report() (Report,error) builds the shared safe normalized projection and counts. Keep Operation fields explicit; do not embed contract.Item or library.MCPDefinition.
- func Normalize(p Plan) (Plan,error): validate action/outcome values and required display identity, deep-copy mutable slices/pointers, derive markers/counts via the common report projection, and establish canonical display order. Reject invalid inputs with safe errors that identify field/operation position without dumping payloads. Do not silently drop operations.
- func RenderText(w io.Writer, p Plan) error and func RenderJSON(w io.Writer, p Plan) error. Both use the same normalized report projection. Plan.MarshalJSON() ([]byte,error) should reuse it so embedding in CLI JSON cannot bypass safe projection or diverge in fields/counts. RenderJSON emits one object plus newline; marshal/validate completely before writing, and propagate writer failures.
Canonical order is target ID, then harness fallback for targetless diagnostics, entry, path, key, section, member, action; tie-break other displayed fields deterministically. Sorting is for presentation only and MUST NOT be used as execution order. Group text by target ID; for targetless diagnostics group by harness (or an explicit unresolved group). Notes have stable harness/code/message order. Renderers must not mutate caller slices or reorder fragment source content.

Text/report details
One physical operation per line: glyph, action, type:name, project-relative path plus JSON key / array member / Markdown section as applicable; symlinks show "-> link". Include outcome and safe skip/failure reason when supplied. Invalid/unresolved entries may have no path; display entry/harness/reason instead of inventing a path. Shared targets appear once regardless of native readers. Targetless unsupported pairs remain separately visible.
MCP rows show command plus every argument or URL from MCPPreview, followed by sorted required variable names; keep ${VAR} and ${VAR:-default} literal. Quote/escape individual command/argument strings so argument boundaries, spaces, quotes and empty arguments are visible; this is display text, never a shell command. Escape CR/LF/tab/control characters in all untrusted display fields so one operation stays one line and no ANSI/control sequence is emitted. JSON keeps structured Args and URL. Never print environment/header values, whole definitions, adapter bytes, JSON values or raw errors. RequiredVariables refers to external variable names (e.g. DAYPACK_TEST_SECRET), not env-map keys like TOKEN. It deliberately excludes optional defaulted references; no new secret parser.
A final summary always counts all six glyphs and outcomes. Empty plan renders an explicit no-changes summary. A final report uses the SAME operations with Applied/Skipped/Failed/Unchanged and reasons provided by executor; it must distinguish a planned change from a completed one. Caller is responsible for safe Reason/Note strings and raw reference-only MCP input; do not promise heuristic redaction of arbitrary plaintext credentials.

Gate predicate and policy
Add func NeedsConfirmation(entry contract.Entry, previous *library.MCPDefinition) bool. Library entries (Inline=false) and non-MCP entries return false. Inline MCP returns true if previous=nil, or raw command, ordered args, URL or transport Type differs; nil/empty args are equivalent. Changes only to description/env/headers do not trigger this executable gate. Compare raw templates, not expanded values; changes to secret values alone do not gate. This predicate is for candidate create/update/adopt operations, not deletion; remove/no-op/diagnostic operations are never gated.
"previous" means the prior managed MCP definition verified against the lock's owned item/current content by the FUTURE planner; an arbitrary handwritten current server is not prior consent. A matching lock row alone is insufficient; absent/missing/drifted/unverifiable history supplies nil and gates conservatively. Current lock schema stores content hashes only: downstream apply must recover a raw definition from verified owned config where possible, otherwise pass nil. This issue neither reads current config nor persists fingerprints. Unit tests inject previous definitions. Do not gate a trusted library server merely because a new worktree has no lock.
Apply the entry's gate to ALL associated mutations (including approval-list entries) so skipping the server cannot leave an approval side effect. This propagation is future planner responsibility; exercise a hand-built multi-operation inline server here. Deduplicate names for one confirmation prompt.
Provide type GateMode string with None/Prompt/Skip/Preview and func ConfirmationMode(p Plan, interactive, yes, dryRun bool) GateMode. No gated candidate -> None. dryRun -> Preview without prompting or changing outcomes; yes -> None; interactive -> Prompt; otherwise Skip. JSON is forced non-interactive at CLI boundary. Provide func SkipGated(p Plan, reason string) Plan returning a deep copy, marking only gated candidate operations Skipped, preserving every non-gated operation for execution and retaining flags/reasons. Conflict/drift/unresolved/unsupported are non-writing diagnostics, not permissions to write. Gate approval is separate from --adopt/--force and never bypasses ownership.
Auto-apply's stricter rule (never apply inline MCP) belongs to the hook/apply issue; do not implement it here or confuse it with manual --yes.
