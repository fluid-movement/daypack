Implementation context (enrichment only; no implementation exists yet)

Repository and scope
- At enrichment, tracked source consists only of `.gitattributes`; there is no Go module or code to preserve. This issue establishes module `github.com/fluid-movement/daypack`. Machine `go version` is `go1.27.3 darwin/arm64`; write `go 1.27.3` in `go.mod`.
- Create `cmd/daypack/main.go` with only process I/O/exit wiring; `internal/cli/root.go`, `internal/cli/run.go`, `internal/cli/output.go` for Cobra construction, execution, flags and presentation; and compilable package skeletons `internal/library`, `internal/manifest`, `internal/lock`, `internal/plan`, `internal/apply`, `internal/adapters`. A `doc.go` with a package declaration is enough for each empty core package. Create `internal/adapters/registry.go` as an empty registry placeholder; concrete adapters will be registered one per line by their feature issues. Do not fabricate an adapter interface before its issue.
- Operations belong in these importable internal packages, independent of Cobra. Dependencies flow from CLI into core; core must not import CLI or Cobra. `cmd/` contains no business logic. Internal packages are importable by future frontends in this module; this does not require a public external SDK.
- Use `github.com/spf13/cobra`. The shared parsing dependency for subsequent issues is `github.com/BurntSushi/toml` (use consistently rather than introducing a second TOML parser). Later JSON editing uses `github.com/tidwall/gjson` and `github.com/tidwall/sjson`, to preserve unowned JSON content; do not add unused dependencies or JSON editing now. Use standard `testing`; no assertion framework. Commit-worthy implementation later includes reproducible `go.mod`/`go.sum`; enrichment creates neither.

CLI boundary and signatures
- Provide `type IO struct { In io.Reader; Out, Err io.Writer; IsTerminal func(io.Reader) bool }`, `func NewRootCommand(streams IO) *cobra.Command`, and `func Run(ctx context.Context, args []string, streams IO) int` in `internal/cli`. Build a fresh command tree for every invocation. Main calls Run with os streams and os.Exit only after Run returns; no exits inside Run or packages. Actual terminal detection must inspect a terminal file descriptor, not infer TTY from an io.Reader being non-nil; it can use `golang.org/x/term`. Inject detection for tests; non-file readers default to non-TTY.
- Use an invocation options value with JSON, Quiet, NoColor booleans and ProjectDir, LibraryDir strings. Persistent flags: `--json`, `--quiet`, `--no-color`, `--project <dir>`, `--library <dir>`. Explicit library overrides DAYPACK_HOME, then XDG_CONFIG_HOME/daypack, then home/.config/daypack. Explicit project directory is passed to all project operations; later manifest loader owns upward discovery. Capture flags once per invocation and pass options explicitly; no mutable singleton state. Blank explicit directory overrides are usage errors. Resolve relative supplied paths relative to the invocation working directory.
- Command layout follows the recorded decision: project `init`, `add`, `remove`, `list`, `apply`, `status`/`check`; global artifact operations under `library init|import|add|edit|rename|remove|doctor`. These operations are later issues: do not install fake successful placeholders. Root help and the reusable contract are enough here; use test-only commands named status/apply to exercise their result paths without implementing them.
- Root persistent flags must be inherited by every later leaf. Disable Cobra's default completion command. Silence Cobra's automatic errors/usage so Run renders exactly once. Help remains available; JSON help/root invocation must also use one envelope rather than raw help text. Usage failures must retain JSON mode even when parsing fails after `--json`; handle both `--json` and boolean assignment forms without running command logic.
- Define exit constants Success=0, Error=1, Usage=2, Attention=3 and a typed command result/error mapping at the CLI boundary. Core errors carry causes/problems, never call os.Exit. Provide a JSON envelope with `ok bool`, `command string` (canonical command path, e.g. `daypack library doctor`), and command-specific `items`, `operations`, `problems` as applicable. `ok` is true only for exit 0; valid input needing attention is exit 3 with ok=false. Encode once followed by a newline; never append status lines, banners, progress, ANSI color or a second JSON object to stdout. Keep human-readable error diagnostics on stderr as well; causes/hints must not contain secret values.
- Classification: invalid manifest/library input, doctor validation errors, I/O/internal failures -> 1; unknown command/flag, bad argument count or flag syntax -> 2; valid pending status/dry-run changes, drift, collisions, unresolved/unsupported skips or gated entries -> 3. Warnings by themselves do not make invalid input. Later commands return a typed outcome rather than guessing code from error text.
- Human errors use a single-line cause and, where possible, a single-line hint on stderr. Quiet suppresses optional chatter, not errors or the required JSON object; no-color suppresses ANSI. Preserve JSON output on errors including usage errors.
- JSON implies non-interactive regardless of stdin. Non-TTY input never prompts. Only later gated apply may prompt; --yes is an apply flag, not a new global flag. Library entries are trusted. Inline MCP first apply or changed command/args/url is gated; without TTY/--yes apply skips gated operations, applies non-gated operations and returns 3. This issue supplies the invocation capability/result plumbing; it does not implement that gate.
