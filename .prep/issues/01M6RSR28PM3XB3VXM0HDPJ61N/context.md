Concrete package API to implement (new API, not existing symbols)
- `func LoadManifest(path string) (*Manifest, error)` reads exactly the supplied file, parses and checks structural schema. Keep I/O/syntax errors distinct from semantic Problems, never echo secret-bearing input lines in errors.
- `type Entry struct { Type library.ArtifactType; Name string; Harnesses []string; Inline *library.MCPDefinition }`; Inline is non-nil only for inline MCP. `type Manifest struct { Version int; Harnesses []string; Skills, MCP, Fragments, Agents []Entry; InlineMCP []Entry }` plus retained source bytes/path and any private parsing metadata needed by diagnostics/editing.
- `func (m *Manifest) Entries() []Entry` returns normalized references with effective harness sets: omitted per-entry harnesses inherit the manifest selection. Preserve each type's array order, especially fragments; append inline MCP in deterministic name order (TOML tables do not define fragment order). Return copies, avoid aliasing internal slices/maps. Ref strings are `string(entry.Type)+":"+entry.Name`.
- `type Problem = library.Problem`; `func (m *Manifest) Validate(lib *library.Library) []Problem` validates all references/collisions and returns deterministic structured diagnostics. Consumers must refuse error-severity Problems before apply; LoadManifest alone cannot resolve names without a library argument.
- `func FindProject(start string) (string, error)` returns the directory containing the nearest `daypack.toml`. Inspect that directory before stopping at `.git` (directory OR worktree file) or filesystem root. Do not cross that boundary into a parent repo. A missing manifest suggests `daypack init`; distinguish permission/read errors from absence.
- Low-level edit API: `func AddEntry(data []byte, kind library.ArtifactType, entry Entry) ([]byte, error)` and `func RemoveEntry(data []byte, kind library.ArtifactType, name string) ([]byte, error)`. These return bytes, never write disk. Support safe, recognized array layouts, parse before/after editing, preserve unrelated bytes/comments/order. Return an actionable error containing `edit daypack.toml by hand` and the exact entry/line to add or remove when a layout is ambiguous. Do not re-encode the entire manifest. No CLI commands in this issue.

Reuse actual library code
- `internal/library/load.go`: `library.Load(libraryPath string) (*Library,error)` discovers artifacts and collects validation Problems; it does not reject all bad artifacts via its error result. `(*Library).Validate() []library.Problem`, `.List(kind library.ArtifactType) []library.Artifact`, `.Resolve(ref string) (library.Artifact,error)` are in `types.go`/`resolve.go`.
- Constants are `library.Skill`, `library.MCP`, `library.Fragment`, `library.Agent` (singular values). Use `Resolve` for missing-name suggestions; `*library.NotFoundError` carries Type, Name, Closest, and `*library.ValidationError` carries Problems. Invalid existing references must also fail validation; no second fuzzy-name algorithm.
- `library.MCPDefinition` fields: Description, Type, Command, URL string; Args []string; Env, Headers map[string]string. `library.ParseMCP(data []byte, source string) (library.MCPDefinition, []library.Problem)` preserves field presence and performs validation, including unknown fields; `library.ValidateMCP` and `.RequiredVariables()` exist. Strip only inline targeting metadata `harnesses` before passing the MCP payload through ParseMCP (decode a raw TOML table, re-encode that payload if needed). Do not merely construct MCPDefinition and lose explicitly empty forbidden fields. Keep unknown inline MCP fields visible to this shared parser. Do not evaluate references, spawn commands or duplicate secret validation.

Schema/edge cases
- Implement exactly the requirement's root keys version, harnesses, skills, mcp, fragments, agents, inline; reject unknown keys with key paths. Version 1 only; unsupported version and wrong field types get clear errors. No speculative templates/hooks key now: future optional keys can be deliberately introduced in a future version; current acceptance explicitly rejects unknown keys.
- Each array element accepts string or table with name and optional harnesses; reject malformed tables/unknown targeting fields and unknown harness names. An explicitly empty restriction must not silently become an omitted restriction; retain presence and diagnose unusable selections. Validate restrictions as subsets of selected harnesses, including inline MCP. Use the library's name convention (1-64 lowercase letters/digits/hyphens); diagnose duplicate references/harnesses rather than generating duplicate desired operations.
- Inline definitions are only `[inline.mcp.<name>]`, independently included without needing an mcp array entry. Check every inline name against `lib.List(library.MCP)`, even if the library server is not selected, and report collisions. Reject inline skills/fragments/agents. Inline secret behavior is exactly the shared MCP parser policy: hard errors for literal secret-looking env/header keys; suspicious args/URL are warnings, not a newly invented detection policy. All diagnostics must avoid raw secret values.
- Manifest validation reports configuration errors; unsupported capabilities such as agents selected for pi are check/adapter notes, not manifest errors. Keep the manifest package independent of concrete adapters to avoid a manifest/adapters import cycle.
