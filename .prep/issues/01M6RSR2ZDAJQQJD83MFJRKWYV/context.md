Ownership composition and important representation trap
internal/lock/json.go provides SetJSON(data []byte,i lock.Item,value []byte) ([]byte,error), RemoveJSON(data []byte,i lock.Item) ([]byte,error), HashJSON([]byte) (string,error). status.go provides (*Lock).Status(root string,i Item) (Observation,error) and RemoveOwned(root string,i Item,roots []string) error. types.go supplies New, Put, Find, Items, Forget; Save(root)/Load(root) persist ownership. path.go IsTracked(root,path) (bool,error); atomic.go WriteFile(root,path string,roots []string,data []byte,mode os.FileMode) error; exclude.go UpdateExclude(root string,items []Item) error and ExcludeBlock(root string,items []Item) (string,error) already handle Git/worktrees.

contract.Item.Value and lock.Item.Value are DIFFERENT representations for array elements: adapter Value is JSON bytes containing the quoted name; json.Unmarshal into string for lock.Item.Value (raw name). Do not use string(item.Value) for the lock array membership: that would own a name containing quotes. For JSONEntry set lock.Item.Hash=lock.HashJSON(item.Value) and pass item.Value to SetJSON. For array membership set lock.Item.Value=decodedName; SetJSON uses that raw name and ignores its value argument. SetJSON/WriteFile are mutation primitives, not collision authorization: call Status first, refuse collisions/drift, propagate Observation.Preserve when adopting a pre-existing approval, then Put/Save the resulting row. An identical unowned server can be adopted using existing ownership policy; a different handwritten server with the same name is a collision. Never overwrite a conflict merely to satisfy the render output.

Tracked and Preserve exist only on lock.Item, not contract.Item. Core/test composition computes IsTracked separately for each file before changes, preserves that classification and uses UpdateExclude. A new .mcp.json and an untracked .claude/settings.local.json are excluded; tracked files remain tracked and must not receive exclude rules. Shared file rows must agree on file tracking. Existing unrelated servers/top-level keys, settings keys and approval memberships must survive. Existing approved names are adopted with Preserve=true and survive cleanup; newly added managed approvals are removable. RemoveOwned leaves JSON containers/siblings intact and refuses drift. No lock format migration, new Git helper or adapter I/O is needed.
