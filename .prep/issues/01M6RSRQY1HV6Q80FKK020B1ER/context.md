Scope and readiness
Implement project-scoped Pi MCP rendering through the existing adapter/registry/ownership architecture. All four declared dependencies are done and their APIs exist on main. No implementation depends on the unfinished Claude MCP adapter, shared-skills adapter, secret-source package, plan model or apply/status commands. This issue adds a pure renderer, registry diagnostics/notes seams and offline integration tests composing the existing lock APIs. Actual disk reconciliation, plan computation, public CLI commands, git-exclusion policy, inline execution confirmation and detecting Pi's actual trust state remain with their owning issues. Do not create a second adapter framework, MCP schema, ownership system or placeholder successful CLI verb.
The requirement has an embedded historical Acceptance section and a standalone checklist. Preserve the stated no-exposure decision and conservative expansion restriction. The trust requirement is implemented now as a selected-Pi project-trust note exposed to consumers; it is a requirement/hint, not a claim that a project was inspected and found untrusted. The future status/check consumer displays it. Main has no such commands to wire today.

Field capability diagnostics — extend the existing contract, not Adapter's interface
In internal/adapters/contract/types.go add Fields []string to existing Unsupported (nil for unsupported artifact types), and define type UnsupportedError struct { Fields []string } with func (*UnsupportedError) Error() string returning a fixed safe message. This error contains field names only, never payload strings, and indicates an otherwise valid entry the harness cannot represent. Private field detection returns sorted unique field paths: "command", "url", "args[0]", "env.TOKEN", "headers.Authorization", etc.
In internal/adapters/merge.go catch this error using errors.As before the existing generic error branch. Append one contract.Unsupported{Harness:name,Entry:entry.Ref,Type:entry.Artifact.Type,Fields:<cloned sorted unique paths>} and continue processing the next selected pair. Ignore any accompanying items for that failed pair; no partial entry output. Keep type-level unsupported behavior unchanged (nil Fields), retain redaction/abort on other errors, retain stable entry/harness ordering, and isolate Fields slices. Add tests for wrapped errors and typed-vs-generic behavior. This preserves other entries and harnesses when Pi cannot render a field. No raw error or definition should enter public diagnostics.
Reject a server containing a ${...} reference in command, URL or any args element, naming every affected field, even if it also has valid env/header references. Research has not verified those positions. Also treat ${VAR:-default} in env/headers as unsupported at those fields: library accepts defaults, while Pi's recorded variable-name syntax establishes only simple variable references there. Preserve simple ${VAR} in env/headers exactly. Do not infer support from RequiredVariables() returning an empty list for a default. Do not broaden to new syntax or assume bare $VAR in command/args/url is verified; it should likewise be unsupported if used as a variable reference, whereas ordinary dollar characters and already escaped dollars must not be mistaken for references. Make detection deterministic, with tests for escaped dollars and ordinary punctuation; it must respect the finding's $$ literal-dollar behavior in env/headers. Do not execute or synthesize per-value !command helpers. Existing literal values remain literal adapter output; any Pi runtime interpretation is outside this renderer.
