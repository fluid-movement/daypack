A justfile at the repository root with the everyday developer recipes, so contributors and agents use one vocabulary (also what CI should call).

Recipes:
- default: list recipes (just --list).
- build: go build -o bin/daypack ./cmd/daypack (bin/ is git-ignored).
- install: build and put the binary on PATH: copy to ${DAYPACK_INSTALL_DIR:-$HOME/.local/bin}/daypack (create the directory if missing), print where it went and warn if that directory is not on PATH.
- uninstall: remove that installed binary.
- test: go test ./...; test-race adds -race; test-v for verbose; cover prints coverage.
- vet, fmt (gofmt -l check that fails on unformatted files), lint (golangci-lint run, with a clear message if not installed).
- check: fmt + vet + test (the local definition of green); ci: the same plus lint, matching the CI workflow.
- clean: remove bin/.
- run *args: go run ./cmd/daypack {{args}}.
- prep-check: prep check.

Constraints: plain POSIX shell lines, no recipe depends on anything outside Go, just and (for lint/prep-check) the named tools; recipes are documented with comments shown by just --list.
