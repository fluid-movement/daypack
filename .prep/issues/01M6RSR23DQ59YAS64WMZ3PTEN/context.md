Actual APIs to build on
- `library.DefaultPath() (string,error)` resolves DAYPACK_HOME then XDG_CONFIG_HOME/daypack then HOME/.config/daypack. `library.Load(path string) (*library.Library,error)` accepts an explicit directory; do not accidentally replace cli.Options.LibraryDir with a second environment lookup.
- `(*Library).List(kind ArtifactType) []Artifact`, `.Resolve(ref string) (Artifact,error)`, `.Validate() []Problem` exist. Artifact fields: Type, Name, Path, Description, MCP *MCPDefinition. Kinds are Skill="skill", MCP="mcp", Fragment="fragment", Agent="agent". References are singular `type:name`; only names matching `^[a-z0-9-]{1,64}$` are valid. Uniqueness is per type, not global.
- `Load` returns a library with invalid artifacts and collected Problems; successful Load alone does not prove validity. Resolve rejects invalid artifacts with *ValidationError{Problems}; missing names use *NotFoundError{Type,Name,Closest}. Keep doctor able to list invalid artifacts; edit/remove should be able to target malformed native files by a validated name/path, so users can repair them without Resolve requiring them already valid.
- `Problem` has Severity (library.Error/Warning), File, Field, Message, Hint. `ParseMCP(data []byte, source string) (MCPDefinition, []Problem)` and `ValidateMCP` already enforce stdio/http schema, references and secret-looking fields; reuse them. Native skill/agent frontmatter validation is currently private metadata(data,source,kind,name). Factor shared validation privately within library rather than duplicating or weakening it.

Concrete new core API (proposed implementation signatures)
- `func Init(path string) error` creates a new library root and skills/, mcp/, fragments/, agents/ plus .gitignore with `/secrets.env` (root-only exclusion). Refuse any existing destination (including empty directory, file or dangling symlink) without writing into it. Never overwrite a user's .gitignore. Do not initialize Git or create a secrets.env file; secret sources own the latter.
- `type AddOptions struct { Type ArtifactType; Name, Source string }`; `func Add(path string, opts AddOptions) (Artifact,error)`. Empty Source makes a valid stub; Source imports native content. Validate type/name and destination absence before copying; stage and validate content before publish. Do not fail a valid addition merely because an unrelated existing artifact has doctor problems.
- `func EditPath(path string, kind ArtifactType, name string) (string,error)` resolves a safe existing native path without demanding valid content. Return skills/<name>/SKILL.md for skill, mcp/<name>.toml, fragments/<name>.md, agents/<name>.md otherwise.
- `func Rename(path string, kind ArtifactType, oldName,newName string) (Artifact,error)` and `func Remove(path string, kind ArtifactType, name string) error`; `func Doctor(path string) ([]Problem,error)` combines Load.Validate with secrets.env Git hygiene checks. No core function prints, prompts, opens an editor or returns Cobra types.

Command surface / CLI contract
- Register one `library` group from NewRootCommand in `internal/cli/root.go`, with init/add/edit/rename/remove/doctor children. Use `SetHandler(*cobra.Command, Handler)` for every leaf; Handler is `func(context.Context, Options, []string)(Result,error)`. Respect persistent --library, --project, --json, --quiet, --no-color and Interactive already computed in root.prepare.
- Concrete positional syntax: `library init`; `library add <skill|mcp|fragment|agent> <name> [--from <path>]`; `library edit <type> <name>`; `library rename <type> <old-name> <new-name>`; `library remove <type> <name>`; `library doctor`. Use Cobra ExactArgs/NoArgs so usage failures cannot run operations. Paths may contain spaces and shell punctuation; pass them as arguments, never interpolated command strings.
- root.go owns IO{In,Out,Err,IsTerminal}, Options{JSON,Quiet,NoColor,ProjectDir,LibraryDir,Interactive}. output.go has Result{Code,Items,Operations,Problems,Help,Message}, Failure{Code,Cause,Hint}, and codes Success=0/Error=1/Usage=2/Attention=3. Run renders exactly once; no handler writes ad hoc JSON or optional chatter to stdout. Use typed item/result payloads (no bytes of artifact content or secret values). Operation/validation failure exits 1; invalid syntax/type/name arguments exit 2; doctor warnings-only exits 0 with structured Problems. Doctor error-severity findings exit 1 while preserving the whole structured list, not replacing it with a single string (return Result{Code:Error,Problems:...} with a suitable message).
- edit requires nonempty $EDITOR; use an injectable runner in CLI tests and os/exec.CommandContext in production with the artifact path as a separate argument. At minimum support an executable path in EDITOR; if supporting conventional editor arguments, parse quoting deliberately without interpolating the artifact path into shell code. No fallback editor, tool editor, or wait on stdin in --json mode. A JSON invocation is non-interactive: do not launch a terminal editor there; return a clear error/hint to edit the reported native path outside JSON mode. Interactive edit attaches the command's streams and waits; editor failure exits 1. This keeps non-interactive command contracts intact.
- rename/remove warnings must be visible in the human result and structured JSON Problems/warnings: manifests using the old name will fail until updated. Do not put this only in Result.Message, which JSON omits. `--quiet` may suppress optional human text but must retain required diagnostics/warnings. No registry, manifest scan or auto-healing.

Mutation details / edge cases
- Stubs: skill directory with SKILL.md containing YAML name equal to destination name plus nonempty description/body; agent .md with matching name and nonempty description; fragment plain markdown (description frontmatter optional); MCP .toml containing description, type="stdio", command="echo", args=[] or another harmless syntactically valid non-secret stub. Do not run the stub. All stubs must resolve and have no validation errors immediately after Add.
- Imported skills copy the entire folder, including support files and nested directories, with SKILL.md required. Other kinds take one native .toml/.md file. Reject duplicate destination even if invalid content or symlink; preserve existing bytes. Validate imported frontmatter against the requested name and reject mismatches with actionable guidance rather than silently inventing a new source identity. Never modify the source tree. Handle symlinks conservatively: reject imported symlinks/paths escaping the source; do not recursively follow into real HOME or copy special files. Test a symlink at the destination/parent too.
- Rename changes only the native artifact path and required YAML name for skills/agents. Preserve all other frontmatter keys, description, body, support files and line endings; use yaml.Node or a narrow validated field edit, not re-encoding the full Markdown document. Fragments and MCP do not gain a name field. Refuse destination collisions and invalid new names; old==new can be a documented no-op. Stage/validate frontmatter changes before moving so failures leave the original valid. Renaming malformed skill/agent frontmatter must fail without partial changes; edit/remove still work for repair.
- Remove exactly the selected artifact file/folder and nothing outside it. Do not follow a directory symlink during RemoveAll; validate root/target confinement, guard names, and reject ambiguous/symlinked parent paths. No cascade to projects, no deletion of global secrets or .gitignore.
- Use same-directory staging and atomic rename for file replacement/publication; cleanup temporary data on error. Do not overwrite duplicates due to a race between existence check and creation; at least exclusive creation/publication guards must preserve prior artifacts. Keep errors secret-safe and include source/destination path plus action, not raw MCP literals.

Doctor Git hygiene
- Report all loader Problems, with paths and stable ordering. Add an error when secrets.env is tracked or not ignored. Use argument-array subprocess calls (no shell), `git -C <library> ls-files --error-unmatch -- <relative secrets path>` and `git ... check-ignore --no-index -- <relative secrets path>`; check-ignore needs --no-index so a tracked-but-ignored file can be distinguished from an unignored file. Handle a library nested within a Git repo and worktree `.git` files. Do not require secrets.env to exist before testing its ignore rule.
- Outside Git there is no tracked-file check; verify the library .gitignore contains the root `/secrets.env` or equivalent `secrets.env` rule created by Init and diagnose its absence. Do not initialize Git during doctor. Within Git inspect effective ignore behavior, including negation rules, rather than only searching for a literal line. Git failures inside a repo must not masquerade as clean status. Do not print secrets.env contents, env values or secret-bearing parser errors.
