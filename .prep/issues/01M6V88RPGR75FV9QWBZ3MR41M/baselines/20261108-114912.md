So an agent running inside the library folder knows how daypack works (only there, not globally): library init also writes an AGENTS.md at the library root describing the layout, record schemas and commands of this daypack version. AGENTS.md only; no skills (it is universal across harnesses, so no per-harness implementations). Generated from the binary so it never drifts; user notes can be added outside generated markers. Re-running library init (or library doctor --fix) adds or refreshes it in an existing library without touching records.
