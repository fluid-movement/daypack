Scope and established requirements
Implement FR-21 using the existing pure adapter contract: project-scoped Claude Code agents are copies of library agents, one whole-file item per entry. Preserve native bytes, including YAML, optional Claude fields and Markdown. Do not render/re-serialize YAML, expand variables, execute agent instructions, import user agents, or verify symlinks with a live harness. No code changes were made during enrichment.

Relevant knowledge:
- [Claude Code conventions](/findings/01M6TETMWQSAMYAGRMW5T045MG.md), section 2: Claude recursively discovers project .claude/agents Markdown; required YAML name and description; malformed agents are silently skipped; project beats user. Agent symlink support is unverified, hence copies. Recursive discovery describes Claude, not a requirement to change the flat library layout or import nested project agents.
- [Per-artifact harness targeting](/decisions/01M6V6XA6XGGF39NCZE9PW5WWA.md): omitted restriction inherits selected harnesses; explicit restrictions select entry/harness pairs.

- [Project lock ownership](/decisions/01M6RVX4S7600YVGAAE9282MYS.md): owned paths and hashes distinguish library updates from destination edits; handwritten files are protected.

Use one adapter for harness name claude-code, never one registration per artifact type. Suggested public shape building directly on contract:

    type Adapter struct{}
    func New() *Adapter
    func (*Adapter) Name() string
    func (*Adapter) Supports(t contract.ArtifactType) bool
    func (*Adapter) Targets() []contract.Target
    func (*Adapter) Desired(e contract.Entry, p contract.Project) ([]contract.Item,error)
    func (*Adapter) Notes(p contract.Project) []contract.Note

For the present baseline Name returns "claude-code", Supports includes library.Agent, Targets includes `{ID:contract.ClaudeAgentsDir, Root:".claude/agents", Mode:contract.DirectoryRoot, Types:[]contract.ArtifactType{library.Agent}}`, and Notes can return nil. When other Claude artifact handlers land, retain their capabilities, declarations and dispatch in this same adapter. Return independent target slices/Types; no mutable global target data escapes.

Return exactly one item:

        Target: contract.ClaudeAgentsDir, Entry: e.Ref, Kind: contract.File,

Link/Key/Marker/Value stay empty. Do not derive bytes from Description or use Artifact.Path as a symlink; no BOM/newline normalization or frontmatter/body edits. Copy bytes so callers cannot mutate Entry.Content via the returned item.

Composition and ownership boundary
The future plan handler loads/validates the manifest and library, resolves agent:<name>, reads Artifact.Path as exact bytes, converts with contract.FromManifest, and calls Registry.Desired with Project{Root:projectDir,Harnesses:m.Harnesses}. No new helper/API for this orchestration is required here. Claude-only selection yields a File item; both harnesses unrestricted yield the Claude File plus Pi Unsupported; a Pi-only manifest or agents restricted to Pi yields only Pi Unsupported and no Claude item. A valid unsupported selection must pass manifest validation. Unknown/unselected restrictions remain errors.

For each rendered File, engine-owned conversion is lock.Item{Target:item.Target,Entry:item.Entry,Kind:lock.File,Path:item.Path,Hash:lock.HashBytes(item.Bytes)}. A managed copy still matching its previous hash remains State=OK,Converged=false after the library source changes. Only after a successful disk write should the new hash replace the prior lock row and be saved. A destination hand edit is Drifted. This issue must prove those semantics through existing lock APIs; no hash of source path, metadata, timestamps or normalized YAML.
